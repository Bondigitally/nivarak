PART I — HIGH-LEVEL DESIGN (HLD)

1 System Context

1.1 What Is Nivarak

Nivarak is a healthcare platform for elder care that manages patients, caregivers, clinical staff, visits, vitals, risk scoring, task orchestration, alerts, and compliance. It is designed to support:

  • Independent ageing assessment via the IAS-P v2.0 clinical instrument
  • Remote patient monitoring and vital tracking
  • Multi-role caregiver coordination
  • Risk-based care pathway routing
  • Automated alert escalation and task management
  • Full audit trail for healthcare compliance

1.3 Architecture Style

Modular Monolith — single deployable, internally structured as independent modules with:

  • Clean module boundaries (each module owns its routes, service, schema concerns)
  • In-process typed event bus for inter-module communication (decoupled via events, not imports)
  • Shared infrastructure layer (DB, auth, logging, errors)
  • Module-level route isolation via Hono sub-apps

3 Security Architecture

3.1 Authentication Flow

sequenceDiagram participant C as Client participant API as Nivarak API participant DB as PostgreSQL Note over C,DB: OTP Login Flow C->>API: POST /auth/request-otp API->>DB: Invalidate old OTPs, store new OTP hash API-->>C: OTP sent C->>API: POST /auth/verify-otp API->>DB: Verify OTP hash, check attempts API->>DB: Load user + roles + linked patients API->>DB: Create session with tokenFamilyId API-->>C: accessToken 15m + refreshToken 30d Note over C,DB: Token Refresh Flow C->>API: POST /auth/refresh Note right of API: Parse tokenFamilyId from token API->>DB: O1 lookup by tokenFamilyId alt Session is revoked API->>DB: REVOKE ALL sessions for user API-->>C: 401 Token reuse detected else Session valid API->>DB: Verify token secret via bcrypt API->>DB: Revoke old session and create new API-->>C: New accessToken + refreshToken end

3.2 Authorization Model (4-Tier)

Request → [Rate Limiter] → [JWT Verify] → [RBAC] → [ABAC] → Handler Tier 0 Tier 1 Tier 2 Tier 3
TierLayerMechanismEnforcement
0Rate LimitingIP-based token bucketrate-limiter.ts middleware
1AuthenticationJWT Bearer verificationauth.ts middleware
2Role-Based (RBAC)requireRoles() guardPer-route middleware
3Attribute-Based (ABAC)requirePatientAccess()Patient-scoped route group

3.3 Role Hierarchy

admin (5) > coordinator (4) > doctor (3) > nurse (2) > caregiver (1) > patient (0)
  • Roles with level ≥ 2 (nurse, doctor, coordinator, admin) have broad access to all patients
  • caregiver and patient are restricted to linked patients via caregiver_links table
  • Inviter can only assign roles at or below their own level

3.4 Session Security

FeatureImplementation
Refresh token format{tokenFamilyId}:{randomSecret}
Token lookupO(1) via tokenFamilyId index
Token rotationOld session revoked on each refresh
Reuse detectionRevoked token reuse → all user sessions invalidated
Max sessions3 concurrent per user (oldest evicted)
Password hashingbcryptjs, 12 salt rounds
OTP brute forceMax 5 attempts per OTP, 5-minute expiry

4 Event-Driven Architecture

4.1 Event Bus Design

  • Type: In-process TypedEventBus wrapping Node.js EventEmitter
  • Typing: Generic emit<K>() and on<K>() with compile-time event payload validation
  • Error handling: Each handler wrapped in try/catch with structured logging
  • Max listeners: 50
