NIVARAK PORTAL SYSTEM
Data Field Specification — 6 Domain Encounter Framework
For Tech Architecture Meeting | Friday
Purpose of this document
This specification defines the data fields required for each of the 6 care domains within a Nivarak encounter record. Every visit — home visit, telehealth, carer observation, or professional assessment — must capture a status indicator for all 6 domains. Fields are organised into three tiers:
TIER 1: Quick Status (mandatory on every encounter — cannot submit without this)
TIER 2: Observation Notes (optional free-text, completed when something is noted)
TIER 3: Escalation Flag (triggers a follow-up action or specialist referral)
💊  DOMAIN 1 — Medical & Medicines
Anchor domain — opens every encounter. Captures current medication status, vitals, chronic condition review, and acute concerns. Most clinicians default to this domain so it sets the clinical baseline for the full record.

⚙️  NOTES FOR THE TECH ARCHITECT
Data model requirements
Every encounter record links to a Person ID — not a visit ID. This enables longitudinal domain comparison across visits.
All Tier 1 status fields must be completed before record submission. System validation at form level — not advisory warnings.
Cross-domain flags (Cognitive + Nutritional; Cognitive + Medicines) are system-generated — not manually entered. Logic runs on submission.
Escalation flags must link to a task or notification record — not just a field value. The system must route the escalation, not just record it.
Even if a simple form/spreadsheet is used in phase 1, field names and value sets must match this specification exactly to enable clean migration.
Role-based access: clinician role (from login) determines which domains show expanded fields vs. quick status only.
Version each encounter record — no in-place edits after submission. Amendments create a new linked record with reason for amendment.
Key questions to resolve in the meeting
What triggers a notification and to whom — care coordinator, GP, family? Where does escalation routing logic live?
Is the interim data collection (pre-portal) Google Forms, Airtable, or a lightweight web form? Must match this field spec.
How are formal screening scores (MoCA, MUST, TUG etc.) stored — raw score only, or full sub-scores?
What is the data retention and GDPR compliance framework — especially for cognitive capacity and safeguarding records?
